# AX 정산 오케스트레이터

발전매출 확정 정산 시 **분개장(412) · 송장 · 세금계산서**를 발전소 단위로 대조하고, 누락·왜곡된 검침발전량을 보정안으로 복구해 매출 정합성을 맞춥니다.

> 기준 등식: 검침발전량(송장) × 확정 단가 = 분개 = 세금계산서

- 운영 DB는 읽기 전용이며, 보정값·예외·보류·이력은 별도 데이터셋에 append-only로 저장합니다.
- 규칙 엔진이 판정하고, LLM은 실패 원인·요약 **설명만** 합니다(근거 숫자 가드 적용).
- 최종 확정은 항상 담당자 승인으로 하며, 확정한 정산월은 잠깁니다.

> ⚠️ 프리즘/BigQuery 조회 · IAP · LLM 연동은 **기능만 구현, 미검증** 상태입니다 → [UNVERIFIED.md](UNVERIFIED.md)

회사 환경(FastAPI · Quasar · BigQuery · Dataform · GKE/Cloud Run · IAP)에 합치는 방법은 **[INTEGRATION.md](INTEGRATION.md)**를 보세요.

## 흐름

```
① 데이터 불러오기 ─ 정산월 → 분개/송장/세금계산서 건수
② 예외 관리       ─ 양수도·수기 발행·거래처 변경·PPA 지연·기타 (유형별 필수값, 버전 이력, 확정월 잠금) + 에러 케이스
③ 3자 대조        ─ 1단계 분개 로드
                     1.5단계 예외 반영 (수기 송장 결합, 일할 안분 — kWh만)
                     2단계 세금계산서 대조 (무효 제외)
                     3단계 확정 단가 역산 (분개 ÷ 검침량, 0.5원 초과 시 미결)
                     4단계 이중계상 · 일 발전시간 99퍼센타일
                     보정 누락 검침량 = 누적값 차이(실제) / 인근 발전소(추정)
                  → 통과 / 자동화 대상 / 확인 대상 / 보류 / 에러
                  → [자동화 시작] 안내창(공식·건수·전후 미리보기) → 실행 → 자동 재검증
                     통과 → 유지, 미통과 → 되돌림 + 실패 원인(LLM)
④ 확인 대상       ─ 원천값·근거·실패 원인·추천 조치·재검증 이력 / [예외 등록] [에러 케이스] [재검증] [보류]
⑤ 리포트          ─ 정산월 종합 · 미결 즉시, PDF 저장(인쇄)
   최종 확정       ─ 보류·미해결 경고 → 확인 후 확정 → 정산월 잠금
```

## 로컬 실행

```bash
# 백엔드 — 가상 데이터(2026-08, 12개소)로 동작
cd backend
uv venv && uv pip install -e ".[dev]"
.venv/bin/python -m pytest -q
AX_DEV_USER=dev@local AX_APPROVERS=dev@local .venv/bin/uvicorn settlement.api.app:app --reload

# 프론트 — http://localhost:9000/settlement (정산월 2026-08)
cd frontend
npm install
npm run dev

# 점검
npm run typecheck && npm test   # 타입 검사 + 단위 테스트
npm run e2e                     # ①~⑤ 전 흐름 E2E (라이트·다크)
```

화면: Pretendard 폰트, 상단 단계 표시(진행중·완료·대기), 라이트/다크 전환(우측 상단), 절제된 전환 애니메이션
